# 专题活动

## 入口与数据范围

- 活动管理下先展示「专题活动」(`/operator/special-activities`)，再展示「征稿活动」(`/operator/activities`)。
- 征稿活动保留原有报名、投稿和激励业务；原来分散在菜单中的活动状态移入列表筛选。
- 专题活动面向运营与管理员，从 `VideoStat` 中按视频发布时间自动匹配稿件，不要求关联平台内的报名或投稿记录。
- 活动开始日和结束日均包含北京时间全天；同一视频可以进入多个专题，各专题独立计算。已隐藏的稿件不参与匹配。

## 筛选配置

活动级筛选支持「满足全部」或「满足任一」：

| 字段 | 匹配方式 |
| --- | --- |
| 视频标题 | 关键词包含，多个关键词可选择全部或任一命中，忽略大小写 |
| 创作者名单 | 按完整 UID 精确匹配 |
| 稿件名单 | 按完整视频链接匹配，抖音标准链接按平台作品 ID 规范化 |

名单可粘贴 Excel 的单列内容，也可导入 `.xlsx`、`.xls`、`.csv` 的首个工作表。导入表头分别为 `UID` 和 `视频链接`，空行与重复项会去除，导入内容与已有名单合并。每份名单最多 100,000 项，文件不超过 10 MB；长数字 UID 应保存为文本，导入时拒绝可能已经丢失精度的数字。

## 奖池与计算步骤

创建和编辑页面将基础信息、稿件筛选、奖池、试算放在同一页面。每个活动最多 12 个奖池，每池最多 20 个顺序步骤：

| 步骤 | 行为 |
| --- | --- |
| FILTER | 按数值或文字条件筛选，支持全部条件或任一条件 |
| GROUP | 按平台与达人 UID 合并，累加指标、稿件数和已有奖励，保留单稿最高推荐播放量 |
| LIMIT | 按指标降序取前 N 项，可作用于全奖池或每位达人 |
| FIXED | 向当前每行增加固定金额 |
| TIER | 按最高命中门槛增加对应档位金额 |
| RANK | 按指标降序，为指定名次区间增加对应金额 |
| RATE | 按指标比例增加奖励，四舍五入至分；可对已有奖励计算加成 |
| CAP | 将当前每行的奖励金额限制在指定上限 |

计算开始时每条稿件是一行，汇总后每位达人是一行，所以步骤顺序会影响结果。例如：

- 单稿阶梯奖、达人封顶：`FILTER → TIER → GROUP → CAP`。
- 达人推荐播放量排名奖：`GROUP → RANK`；可先用 `LIMIT` 保留前 N 位。
- 条数门槛或爆款豁免：先筛合格稿件，再 `GROUP`，用任一条件匹配「稿件数达标」或「单稿最高推荐播放量达标」。

同一互斥组使用相同的组名，而非填写目标奖池名称或编号。奖池按配置顺序计算，同一达人仅保留该组内第一个实际计算出正金额的奖池；未填写组名的奖池可以叠加。上下移动奖池即调整优先级。互斥当前仅作用于本活动，按固定顺序处理，不比较最高金额。

计算使用整数分保存金额，拒绝超过安全整数范围的结果。指标相同时以当前行的键确定排序，不额外并列发奖。规则计算本身不会回写原始视频数据。

## 取数与确认结算

- **确认时冻结**：预估读取最新可用指标，运营确认时重新读取数据并计算，保存确认时的输入和结果。
- **固定截止时间**：截止前预估使用最新指标；截止后，如果最新记录已经晚于截止时间，尝试使用不晚于截止时间的每日快照。
- 每日快照不是任意时刻的完整历史回放；同一天的快照会被当日更新覆盖。没有满足截止条件的历史指标时标记为缺少数据，不冒充精确截止值。
- 按批次读取全部匹配数据，不再以 10,000 条限制试算。独立读取使用同一 Repeatable Read 视图，避免采集更新导致批次漏算或重复。
- 活动结束且数据截止时间已到、存在匹配稿件、没有缺少截止指标时才可确认。缺少达人 UID 的稿件保留在明细中，不参与计奖。
- 试算指纹包含规则和所用稿件数据，确认时发生变化会要求刷新；确认结算使用 Serializable 事务和活动版本检查。已结算活动禁止编辑。
- `SpecialActivity.settlement` 保存版本、配置和完整估算快照；已结算详情和卡片读取该快照。
- 创建、修改、确认分别写入 `specialActivity.create`、`specialActivity.update`、`specialActivity.settle` 审计记录。

## 列表与详情展示

- 列表采用左侧封面、右侧名称与信息的无阴影横卡，展示匹配稿件数、可识别的去重达人数、推荐播放量和预估金额。已结算活动展示结算金额。
- 列表统计采用详情页的同一计算结果，按活动版本及结算时间区分缓存，未结算统计短时缓存 60 秒。统计通过 Suspense 独立加载，失败显示未知状态，避免把失败当作零值。
- 详情顶部是活动概览，下方用「结算预估／结算结果」和「稿件明细」页签切换，URL 的 `tab` 参数记录当前页签，各列表分页与查询条件独立保留。
- 达人列表支持 UID、抖音号、昵称搜索；计奖稿件数和推荐播放量仅统计最终实际参与计奖的稿件，跨奖池去重。
- 稿件明细按推荐播放量降序排列，支持作品 ID、达人 UID、抖音号搜索。标题最多三行，每行最多 20 个字符，超出后以省略号显示，可悬停查看完整标题。
- 达人信息由昵称、抖音号和 UID 组成，使用图标标识，点击可复制，复制图标仅在悬停或键盘聚焦时显示。
- 各奖池金额只在表格内展示前两项；稿件奖池结果展示计奖、互斥、未命中数量，完整内容通过有高度限制的可滚动浮层查看。
- 单位达人的奖励依据使用独立弹窗，稿件按推荐播放量降序分页，保留平台作品 ID、原始排除原因与计算过程。

## 实现位置与边界

- 数据模型与迁移：`prisma/schema.prisma`、`prisma/migrations/20261106090000_special_activities/`。
- 规则校验与计算：`lib/special-activities/rules.ts`、`engine.ts`。
- 数据读取与预估：`lib/special-activities/db.ts`；卡片摘要缓存：`card-summary.ts`。
- 页面：`app/operator/special-activities/`；接口：`app/api/operator/special-activities/`。
- 目前没有手动奖池、按天去重打卡、单稿指标截断、跨活动取最高奖励，也未接入组件挂载、签约身份、内容品质、图文或跨平台关联条件。这些属于后续需求，不由现有基础规则推断。

验证命令：`pnpm typecheck && pnpm test`。
