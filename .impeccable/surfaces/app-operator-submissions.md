# 稿件管理页面设计

Mode: Operate。继承现有 GameOps 后台的视觉体系，不改全局配色和导航组件。

## 卡片入口与角色按钮（当前交付）

稿件审核页上方周期卡片仅展示信息与统计，不再渲染操作按钮或空操作栏。全部稿件页卡片按身份显示：REVIEWER为「前往审核」，直接进入带该周期from/to、PENDING及keepFilters=1的审核列表；OPERATOR/ADMIN仍为「查看详情」。全部稿件页头移除「进入稿件审核」，保留运营/管理员的新建稿件统计。周期详情右上「审核本周期稿件」统一更名为「进入稿件审核」，原日期范围与待审跳转规则保留。权限与数据范围仍由现有服务兜底。

验证：类型检查与52个文件380项测试通过；使用隔离的统计查询进行实际服务端HTML渲染，ADMIN/OPERATOR/REVIEWER六种卡片组合及页头入口校验通过，确认审核页没有链接或空CardFooter、审核员跳转含日期和待审核参数。本地3000网页及配置5433数据库不可用，本轮未完成在线浏览器检查，未更改运行环境或数据库。临时校验脚本已删除。

## 稿件审核：复用周期卡片组（当前交付）

`/operator/submissions/review` 在页面标题下、视频列表上方增加「审核周期」卡片组，直接复用全部稿件已保存的 `SubmissionPeriod` 配置与卡片。保留用户设置的名称、状态、起止日、稿件数、达人数、合格/不合格作品数及各自推荐播放量、审核进度和「查看详情」。默认展示最近1个周期，其余通过「展开其他 N 个周期／收起其他周期」访问；卡片不作为选择器，不改变列表筛选或连续审核范围。组内说明明确卡片按各周期统计，下方列表筛选不改变卡片统计；即使视频列表无匹配，周期卡片仍显示。

运营/管理员看到全部周期及有效视频汇总；审核员仅看到本人有分配的周期与本人有效稿件统计。无周期时分别提示在全部稿件创建或等待运营分配。统计继续按北京时间发布时间包含起止日全天，排除隐藏及空日期视频，请求或刷新时更新，不轮询。本次复用统计周期，不接入征稿或专题活动数据。

`ReviewPeriodCards.tsx` 在服务端编排卡片，`ReviewPeriodCardsDisclosure.tsx` 仅管理 Collapsible 展开状态；两页共用从全部稿件工作区提取的服务端包装器 `SubmissionPeriodSummaryCard.tsx`。审核页面用当前身份调用 `loadSubmissionPeriods({}, actor)`，客户端 `VideoReviewWorkspace.tsx` 以 ReactNode 插槽接入卡片。沿用既有聚合、权限和卡片响应式布局，无新增API、数据模型或迁移；列表角色默认、排序、连续审核、日志和弹窗行为保持既有约定。

本轮验收：`pnpm typecheck` 与全量52个文件380项测试通过；1440px、1070px及390px浏览器检查覆盖默认单卡、三周期展开/收起、列表无匹配、审核员归属及空周期状态。手机默认单卡时「开始审核」位于844px首屏内，页面 `clientWidth` 与 `scrollWidth` 均为375px（390px视口含15px原生滚动条）。截图为 `.impeccable/review/review-period-cards-{desktop,intermediate,mobile,expanded,collapsed-mobile,reviewer,empty}.png`。两条2099年临时周期及临时空审核员已清理，未修改原有视频、分配或审核结果。独立 `review_cards_finish_reviewer` 全范围复核结论为SHIP、material fixes为none；detector仅对6个变更TSX运行一次并返回空结果，无新增生产位图。本文据最终源码与已完成验收更新，未重跑浏览器、测试或detector。

## 运营与管理员列表默认规则（当前交付）

OPERATOR/ADMIN稿件审核列表默认「全部状态」，按VideoStat.reviewedAt降序，无审核时间的稿件置后，同时间按ID降序稳定分页。手动选择状态仍生效，重置与无参数访问恢复角色默认；前端筛选与API查询保持一致。REVIEWER仍默认「待审核」、按发布时间升序，只读取本人分配。发布时间筛选继续使用publishedAt；开始审核与连续审核队列继续按发布时间升序处理待审稿件，不受运营列表的审核时间排序影响。

类型检查与52个文件374项测试通过，覆盖运营/管理员默认全部、显式状态筛选、审核员原有口径和稳定队列。

## 审核日志与取消批量提交（当前交付）

稿件审核页移除全选、行勾选、批量状态和提交栏；仅保留单条与连续审核。原视频批量POST接口鉴权后返回404停用提示，不能继续写入；旧Submission管理接口不在本次页面范围。运营/管理员在表格最右侧增加「审核日志」文字按钮，使用低强调ghost样式，不争夺标题旁审核与顶部开始审核的主层级。审核员不显示日志列，日志API及服务同样限制OPERATOR及以上。

日志弹窗按审核时间倒序、每页20条，展示审核人、固定账号（与显示名不同时）、北京时间、审核状态、完整标签路径和已保存备注；支持加载、空记录、失败重试、分页和关闭。弹窗宽度最多768px、高度最多85dvh，记录区独立滚动，手机保持16px外边距、底部页码与按钮可见。新记录复用AuditLog，审核结果与显示名/时间/标签路径快照同事务写入，失败不报告保存成功；改名不会改写日志。历史单条按tagIds匹配现有标签并注明使用当前名称，旧批量没有标签信息时明确提示，无法恢复的信息不伪造。无日志的当前结果在首次覆盖前保留为早期结果，标签按留存时名称注明；不限制近60天，无需迁移。

验收：类型检查与52个文件372项测试通过。临时稿件真实HTTP验证两次保存、改名快照不变、首次覆盖保留早期结果、批量接口404、审核员日志403且页面日志按钮/多选框均为0；分页使用25条临时记录。1440/1070/390px浏览器检查布局，截图 `.impeccable/review/review-history-*.png`。本轮为既有界面的局部扩展，未变更全局设计体系。

## 周期详情与审核分配（当前交付）

全部稿件卡片只保留可点击的「查看详情」，进入 `/operator/submissions/periods/[id]`；编辑移至详情页的「编辑基本信息」。详情顶部展示周期名称、状态和北京时间起止日，接着显示稿件、达人、合格/不合格作品、待审核及审核进度；「审核本周期稿件」将日期范围带入视频审核工作台。名称最多120字符，详情标题允许连续长字符换行，中间视口和手机端不挤出操作入口。编辑后保存或取消均返回详情；已有分配时禁用起止日期，服务端同步校验，名称和状态仍可编辑。

OPERATOR / ADMIN 可查看全部周期及有效视频统计、编辑基本信息并使用「审核分配」面板；REVIEWER 只看到本人有分配的周期，卡片和详情仅汇总时间范围内本人分配的有效视频，详情不显示编辑及分配面板。归属检查同时覆盖视频列表、待审核数、下一条游标、单条保存、视频预览和周期详情，不能通过直接访问接口绕过；旧 Submission 页面与读写接口仅允许 OPERATOR 及以上。分配归属与实际审核人分开记录，运营仍可审核所有视频。

分配候选仅为周期内按北京时间发布时间计入的有效、待审核且全局未分配视频；隐藏、空日期、已审核及已分配视频均不参与。`VideoReviewAssignment.videoId` 为主键，同一视频在重叠周期也只分配一次，不覆盖既有归属或审核结果。面板显示可分配量、本周期已分配量、其他周期已分配的跳过数量，以及每位审核员的已分配、待审核、已完成数量；停用或角色已变更的历史审核员可保留展示，但不可新选，无可用审核员时显示账户启用提示。

分配面板先集中展示一次审核员当前工作量，再以带编号的字段组编排分配组合；每组独立选择「平均分配」或「指定量分配」，最多20组，支持添加和移除（至少保留1组）。平均分配必须填写「本组平均分配总量」，按该组总量均分给所选启用审核员，组内最多相差1条；「使用剩余量」填入可分配量扣除其他组计划数量后的余额。指定量分配填写每位选中审核员的正整数条数。同一审核员可以参加多组，跨组数量合计；组内不可重复选择同一人，所有组总量不得超过可分配量。例如A/B平均总量1000条，再给C指定300条，可在同一次组合内预览并提交，不需要分两次安排。

各平均组的余数独立随机决定，多分1条的人在确认时确定。服务端先计算各组配额、合并同一审核员，再从全部候选一次性随机选稿，跨组不重复；按平台与非空作者UID尽量把同作者视频分散到所有有配额的审核员，数量约束优先，不承诺作者完全不重复。未使用的候选保留未分配，已有分配及审核结果不覆盖。

「预览分配」展示组数、去重审核员人数、总量与剩余量，逐组展示各人数量，并单列「审核员本次合计」；平均组有余数时展示各人的可能区间，跨组同人的区间累加。组数、选择、模式、数量或可分配量改变均使预览失效；预览冻结本次请求配置，确认只提交该预览。用户可「返回调整」或「确认组合分配」，提交期间禁用编辑和操作；校验错误在面板内显示，平均总量错误聚焦对应输入框。成功后显示已分配与剩余数量，清空为一组空白草稿并刷新工作量。工作量表最小480px，组内审核员表最小420px，由各自容器横向滚动；预览以可换行文字列表呈现，手机不撑宽页面。

确认携带预览时的 `expectedEligibleCount`；服务端候选量发生变化返回409，客户端清除预览并刷新可分配量，要求重新预览确认。一次组合在同一事务内执行，`requestId`、配置哈希、分组配置、最终各人合计、成功结果与 `video.assignment` 审计一同保存；相同已成功请求在候选量检查前优先返回原结果，配置不同则拒绝，不因重试再次随机或写入。继续兼容旧单组请求及其原有哈希：旧EVEN未传总量仍分配全部，新 `groups` 请求的每个EVEN必须显式填写组总量；包含无效 `groups` 的混合请求不可回退为旧单组。分配、审核和周期修改继续共用事务锁7264232，分配锁定候选视频行并对审核员行加共享锁；任一组非法或审核员不可用时整批拒绝。统计在页面请求或刷新时读取最新 VideoStat，不轮询；FROZEN仍仅表示状态，不冻结统计或禁止分配、审核。本次组合扩展无需数据库迁移。

## 全部稿件：视频库周期卡片

全部稿件不再展示征稿/视频明细列表及顶部四张统计卡，改为复用专题活动的横向卡片布局。运营和管理员可新建、编辑并长期保存多张命名周期卡片，审核员仅可读取本人有分配的周期及本人稿件统计；配置存 `SubmissionPeriod`，不关联专题活动或结算。现有用户卡片名称为「7月审核稿件」，周期为2026/07/01—2026/07/31；名称按用户配置展示，不因验收修改真实数据。

每张卡片显示稿件数、达人数、合格作品数、不合格作品数及带百分比的审核进度。合格/不合格作品数分别取 `reviewStatus=APPROVED/REJECTED`，其下推荐播放量分别合计对应视频的 `recommendedViews`；没有独立推荐播放量或金额主指标。达人数按平台+非空创作者UID去重。进度为已审核数（合格+不合格）/总稿件数，空周期为0%，未全部完成时最高显示99.99%，完成后100%。

`lib/submission-period-summary.ts` 直接在数据库聚合最新 `VideoStat`，按北京时间发布时间包含起止日全天、次日零点排除；隐藏和未知发布时间视频不计入。列表不加载视频或作者明细。统计在页面刷新时更新，不使用后台定时刷新。lg起指标与进度五列并排，sm至lg指标四列且进度独占一行，窄屏指标两列且进度横跨两列，无页面横向溢出。「查看详情」链接至周期详情，编辑入口仅在运营/管理员的详情页展示。

## Direction contract

THESIS：总览与审核分开，用户先看清结果，再进入处理工作台；标签维护使用目录树，不再以活动卡片承载所有稿件操作。

OWN-WORLD：沿用现有浅色工作区、白色 Card、边框、sans 字体栈和 shadcn 控件；状态色只表示审核结果或启停状态，数据用等宽数字对齐。 审核弹窗局部采用白色主面、低彩度冷灰输入区/底栏、深蓝灰文字与品牌蓝主操作；浮层、焦点、禁用态共享同一组局部令牌，并为暗色主题配置深蓝灰对应色阶。

STORY：全部稿件以命名周期卡片汇总视频库的稿件数、达人数、合格/不合格作品及审核进度，全部稿件卡片由运营/管理员进入详情编辑与分配，审核员通过「前往审核」直接进入周期待审列表；审核页卡片只展示统计。运营在详情编辑配置、预览确认按总量平均分配与指定量分配的多组组合；审核员仅看本人有分配的周期和本人稿件。稿件审核直接读取视频库，提供作品ID、15字单行标题、发布时间、审核员、审核时间、审核状态、三级标签、标题旁审核按钮及运营可见的末列审核日志，通过顶部主入口连续处理当前身份范围内的待审视频；运营在标签页维护多级目录。

FIRST VIEWPORT：标题左对齐；稿件审核标题下先显示沿用全部稿件样式的审核周期卡片组，默认最近1个，其余可展开；卡片统计独立于下方筛选。视频审核列表标题右侧为40px实心品牌蓝「开始审核」，筛选位于下一行。行内审核紧邻视频标题，辅助信息列收紧。审核弹窗保持固定高度，正文单独滚动，底部固定「保存并关闭」与「保存并审核下一条」。手机保留可见主入口、局部表格横滚与固定弹窗底栏。总览沿用紧凑周期卡片，审核员显示「前往审核」、运营/管理员显示「查看详情」，页头移除直接审核入口；审核页卡片不显示操作按钮。详情首屏以名称、日期、状态与审核统计建立上下文，运营操作为「编辑基本信息」和「审核本周期稿件」，下方进入分配面板；审核员详情仅保留本人统计和审核入口。分配面板先展示可分配量和审核员当前工作量，再以可增减分配组填写模式、组总量或个人条数，最后展示每组与每人合计的预览确认，窄屏保留容器内横向滚动；长周期标题可靠换行。标签目录保留既有布局。

FORM：既有后台的局部扩展，按明确需求直接实现，未进行视觉体系替换或概念抽签；code-led，无设计效果图审批。

QUALITY BAR：审核列表及详情不显示创作者ID，不传递作者资料；周期统计按视频发布时间包含北京时间起止日全天，排除隐藏视频，空周期显示0；日期采用北京时间；标签支持多级归属、排序、停用，防循环与同级重名，保留历史引用；表单输入、选择与复选控件使用项目组件。保存后加载下一条失败时，不重复提交已保存审核。审核员归属在页面和接口均兜底；同一视频全局唯一分配，分配保留已有归属与结果，候选量变化要求重新预览，成功请求重试不重复写入。

## 权限与统计口径

- REVIEWER 仅可浏览本人有分配的周期、本人稿件总览与审核工作台，读取审核标签；不能新建或编辑周期、分配、维护标签或导入易闪结果。OPERATOR / ADMIN 可查看全部并执行管理操作。
- 全部稿件页使用VideoStat命名周期统计卡片，口径与权限见上文；不显示明细列表，不关联征稿或专题活动。
- 稿件审核页直接使用 VideoStat，默认有效视频；运营/管理员默认全部状态、按审核时间降序（空值末尾，同时间按ID降序），审核员默认待审核、按发布时间升序（空值末尾，同时间按ID升序）。日期筛选仍取发布时间；支持查看全部或隐藏视频。审核结果为视频的独立单一状态，不再展示标题、内容、易闪分项审核，也不受征稿活动范围限制。
- 历史四入口停用配置在 `lib/submission-navigation.ts`；旧 Submission 详情与读写接口仅允许 OPERATOR 及以上。运营访问原详情地址时按平台与作品ID匹配视频，匹配成功跳入视频审核并定位，未匹配则回到全部稿件统计页。

## 连续审核工作流

顶部「开始审核」是唯一高强调主入口，从当前搜索、平台、视频可见性及发布日期范围的最早待审作品开始，不受列表页码和审核状态筛选限制。行内审核放在视频标题右侧作为次级快捷入口。弹窗高度固定，正文独立滚动，底部保持可见的「保存并关闭」和品牌蓝「保存并审核下一条」，并记录本次已保存数量。

客户端工作台持有独立 activeRow，列表刷新或分页后仍保留当前审核弹窗。下一条接口沿用 q、platform、visibility、from、to，忽略列表 status、page、videoId，以发布时间+ID稳定游标仅取待审核视频，并将未知日期放在最后；不使用offset，保存造成的队列数量变化不会跳条。下一条失败后，保留已保存状态，禁用已存表单并提供「重试下一条」；重试仅GET，不重复PATCH。成功切换后重置备注及审核状态。队列末尾关闭弹窗并显示提示。

前轮连续审核验证：321项测试包含默认待审队列、过滤范围、同时间ID排序、未知日期、游标缺失和独立鉴权。实际浏览器从列表第二页开始时进入01号验收作品；模拟保存后下一条503，重试进入02号且仅一次PATCH、备注与审核状态重置；24号末尾保存后显示队列尾提示。手机底栏底边809px、弹窗底边810px，确认正文滚动时底栏仍固定可见。24条验收视频已清理。

## 2026-11-18 补充交付

稿件审核提供小型活动选择框，按周期日期切换列表与连续审核范围，弹出列表最多5项高度，可滚动且隐藏滚动条。角色可见选项沿用服务端周期权限。

审核标签右侧按一级标签分区；同级标签统一为对齐的行，展示层级及子标签数量。下级通过缩进与连接线区分，带下级的行可折叠，编辑/新增子标签/删除通过菜单进入。搜索保留父级上下文。
